# DEV 首步非零合并精度 pilot

本轮固定第二个 DEV pilot 的 M0、首个 Oracle 请求、首步公开激活提示与已保存但回滚的 WP adapter。起始状态与 adapter 的 SHA256 固定。重建原试验的 BF16 候选状态哈希是完整性检查。使用原 adapter 对照，不重新拟合首步试验；保存旧的失败产物。

在 12 个编辑层逐层报告激活保护子空间的相对残差 rho。未合并阶段同时测解析更新矩阵及 LoRA 前向在保护基上的作用。合并阶段以真实存储的合并权重减去同值 M0 得到更新矩阵，并报告其与同一理论更新的差。记录有限性、非零性、dtype、状态哈希、公开探针概率及预测。另比较 M0 在两种线性精度下的公开探针结果。独立子进程从原缓存和相同 M0 重做三路。

部署候选的实际合并残差与未合并残差均须逐层不超过原阈值 0.01，独立子进程须重现候选状态哈希和公开选择标签，条件概率差不得超过原 1e-4。按 BF16、FP32 顺序选通过的部署口径。FP32 路径只把 12 个编辑层权重及现有偏置转为 FP32，使用 FP32 线性运算并将输出转换为 BF16 供其他模块使用。保留这些层的 FP32 存储，适配器按同一路径独立重载。报告该精度路径和旧 BF16 路径的初始行为差异。

有口径通过才自动运行同一 DEV M0 上的完整 WP/WN/WR 队列，每个分支 8 个固定 Oracle 请求，沿用 32 步、范数门和确定性种子。三组用相同精度。WP 或 WR 某步超门时按原规则回滚并停止该分支，WN/WR 只运行可匹配的 WP 前缀。WP 的解析残差门仍是原 1e-5。独立评测记录精度匹配初始锚点的行为，D 分母沿用原 14 项并报告初始行为变化。W0/W1 的既有 BF16 结果只作背景。确认性 TEST 关闭。

V8-B 先前已用 0.26052 GPU 小时。本队列最多 2 次主启动、2 次独立重载、24 次训练拟合。GPU 进程墙钟上限合计 190 分钟，新增磁盘最多 3 GiB 并保留至少 15 GiB。原始数据、旧运行和未通过的写回结果均保留。
