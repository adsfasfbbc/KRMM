# V8-B DEV-V8 冻结协议

本批是 Qwen2.5-Omni-3B 的 Oracle DEV，不接触 TEST。36 个新实体按三个历史领域各 12 个冻结，每域四类各三个。每个实体保留两个有来源的同实体事实及一个独立提示的预期 ripple 题。冻结校验包含 v0.3、v0.5、v0.6 和 v0.7 可读目录中的规范化名称和别名，人工排除明显同义实体。原始来源说明、Oracle gold 和隐藏评测题留在服务器 evaluator_private 路径，由私有 SHA256 固定。本批省略可选未知对照；所有题目为自编文本，无原始媒体复制。

先在干净模型上按 v0.7 的筛查与 held-out 定义测掌握。最低 27/36。每域对稳定掌握者以种子 3808 按旧比例 0.45 随机抽取，使用 D1 64 步损伤，重新评估全池。有效退化 D 至少 8。用独立冻结种子 4818 打乱有效退化列表取前 8 条，保留计划和附带损伤。每份模型分支恢复同一新 DEV M0，32 步及原 rank 8 配置固定。无写回 B0 比较 M0 确定性。

W0 使用历史通用 KL。W1 加入历史均衡通用 KL。WP/WN/WR 使用 W1 的同一保留提示、权重和训练步。各分支均收集公开激活，选 4 个普通提示、当前实体和前两个同域实体的公开提示、最近两步已提交的 provisional 历史问法。每层选均匀有效 token 样本，FP32 SVD rank cap 64。WP 在所有 forward 投影 LoRA A；WR 以同层、同维数的固定随机正交基执行同一投影。WN 与 WR 在保存及合并前缩放 B 匹配同一步 WP 有效增量，合并后核查各层实际 Frobenius 范数差不超过 10%。第一步从共同 M0 开始；后续是不同轨迹。写回器在 Linux Landlock 文件访问边界内运行，只读公开数据、模型、M0 和著录的 Oracle 请求；不读隐藏题和审计产物。独立评测器在写回退出后才重新加载。

解析残差阈值 1e-5，实际 BF16 残差阈值 1e-2，逐层检查；实际零更新拒绝。WP 或 WR 第一次数值失败就停止该分支并恢复实际权重。若 WP 提前停，WN/WR 最多完成已有范数参考的前缀，按共同 M0 的首步对照和实际匹配状态报告。禁止用拒绝写回虚增严格收益。写回器不接收隐藏反馈。

强简单对照在完整 8 步的 W0、W1、WN 中按最终同实体与健康损伤、H_ever、主动恢复及 R_final 字典序选择。进入 TEST 准备需 WP 完成 8 步且主动恢复至少 6，R_final 相对强对照损失不超过 10 pp，最终同实体和健康新增损伤为 0，独立重载与严格收益通过。另要求开放配对覆盖至少 50%，完整等范数与随机对照，且 WP 比三种对照有更少的同实体损伤、主动恢复差不超过 1 项。命令队列不含 TEST；只有 DEV PASS 后才准备和冻结独立确认集。

本批上限为 2 次主启动、1 次独立 GPU 评测重载和至多 76 次拟合，三个进程墙钟上限 60、120、40 分钟。新增最多 3 GiB，保留 15 GiB。任何数据门失败保留结果并停止下游。无自动重试，未购置或下载模型。
