# Benchmark interpretation and label audit

This pilot uses four curator-defined acoustic-source options for conventional instrument forms. It is a closed-choice proxy for broad Hornbostel–Sachs families, not a complete organological classification or a full physical account of coupled exciters and resonators. For example, reeds/lips and an air column can both participate in a wind instrument; an atomic answer about the exciter need not identify the intended family. Such cases can defeat the current reconstruction rule set.

The [ICOM MUSIC classification resource](https://icom-music.mini.icom.museum/resources/classification-of-musical-instruments/) confirms the MIMO revision and subsequent addenda. The supplied [MIMO classification document](https://mimo-international.com/documents/Hornbostel%20Sachs.pdf) and [Grinnell celesta collection record](https://omeka-s.grinnell.edu/s/MusicalInstruments/item/971) were located during the audit, but full retrieval timed out / returned 403. This does not constitute a full expert audit of all individual labels. The conventional celesta/piano distinction concerns vibrating metal elements versus strings, rather than the shared keyboard action.

All benchmark labels remain curator annotations pending independent expert verification. No label, original test entity, test question, success threshold, or reconstruction rule is changed in response to a held-out result. Original mastery rates and all exclusions are reported; success fractions are conditional on the preregistered eligible-damage population, not on all instruments or all model knowledge.

The prospective calibration extension adds 12 genuinely different named instruments, not additional paraphrases of existing units. Fine-grained family relationships still induce correlations; entity bootstrap intervals are conditional on this fixed model and benchmark, and do not represent uncertainty across architectures or all instrument families.

## Information boundary

Only evaluator modules contain target truth. The public task schema, constraint rules, feature transform and answer-free service import no evaluator label table. Candidate generation reads only the damaged model and allowed evidence. Damage updates are merged into base parameters; the repairer never disables a damage adapter or subtracts a known damage difference.

The harness retains original selected weights solely to reset independent model copies. This is a logical, source-audited interface boundary, not operating-system isolation from a hostile program. Fresh-process persistence evaluation is an evaluator operation and may reconstruct the exact damaged checkpoint from official unchanged weights plus complete merged changed weights. None of those original-reset references is used by the supplied repair algorithm.
