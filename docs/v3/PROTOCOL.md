# KRMM v0.3 Frozen G0 & P0-P3 Protocol

1. **Model & Environment:** `Qwen/Qwen2.5-Omni-3B` pinned at revision `f75b40e3da2003cdd6e1829b1f420ca70797c34e`, single GPU (`CUDA`), sequential per-unit execution.
2. **Dataset & Split Isolation:** 120 high-frequency commonsense units across 3 domains (`vertebrate_class`, `everyday_material`, `sound_source_mechanism`), partitioned into entity- and `source_group`-disjoint `dev` (36), `calibration` (36), and `test` (48), plus 12 `anchor` units exclusively for training-time retention and 8 `unknown_control` units for M2 false-positive auditing.
3. **Clean Mastery Gate (A):** Unit must score 100% across 4 independent phrasing templates (0, 1, 2, 3) AND 2 option-permutation checks, with minimum choice probability mass >= 0.25. G0 requires >= 75% clean mastery rate.
4. **Damage Validity & Locality Gate (B):** Balanced random wrong-association (`D1`) or targeted suppression (`D2`) must eliminate screening accuracy (<= 0.0) and drop heldout accuracy by >= 0.50, while preserving >= 0.90 train retention agreement AND passing independent 4-category locality audit (`token_agreement >= 0.90`, `accuracy_drop <= 0.05` across `same_entity_other_relation`, `other_entity_unseen_template`, `near_neighbor_invariant`, `general_commonsense`). G0 requires >= 8 independent units and >= 50% strict damage eligibility among mastered units.
5. **Oracle Writeback Gate (C):** Given the ground-truth option on strict-eligible damaged units, constrained parameter repair must recover 100% accuracy on unseen templates (4, 5) + unseen option permutation, reproduce consistently in a fresh Python subprocess, and pass independent locality audit vs damaged state. G0 requires >= 75% oracle strict restoration rate.
6. **Progression Rule:** Only after G0 passes on `dev` do we run P1-P3 (E0-E7 matrix, M2 discovery, M3 reconstruction, M4 decomposed calibration on `calibration`), and only after freezing all thresholds do we touch `test`.
